# Support

This repository provides best-effort community support for the OIP
specification and its reference code. Security reports follow
[SECURITY.md](SECURITY.md).

## Before you ask

Start with the [README](README.md), the [specification documents](spec/) and
the [operation table](spec/operations.md). The published
[OIP v0.6 documentation](https://docs.oraclizer.io/oip-v06/oip-overview/)
explains this version, and the
[OIP v0.5 documentation](https://docs.oraclizer.io/oip-v05/oip-overview/)
describes the previous version.

## Public issues

Use public issues for reproducible defects, specification questions,
documentation errors and focused design proposals. Include the commit,
operating system, tool versions, commands, expected and observed behavior,
and a minimal reproduction. For a message that Rust and Go handle
differently, include the frame in hexadecimal.

Do not use a public issue for an undisclosed vulnerability. Follow
[SECURITY.md](SECURITY.md) instead.

## Supported questions

Maintainer responses may cover the specification text, the message schema,
the Rust and Go reference code, the test vectors, the documented build and
test commands, and the boundaries in [DISCLAIMER.md](DISCLAIMER.md).

The repository does not provide deployment operation, key management,
incident response, legal or regulatory advice, performance guarantees,
integration service levels or support for forks.

## What to expect

Issues are triaged in batches. If a thread has gone quiet, a comment on it is
welcome and is the fastest way to have it picked up again.

Reproducible defects and concrete specification errors are handled first.
Broad questions and large proposals may take longer, or may be answered with
a pointer to the relevant document rather than a full discussion.
