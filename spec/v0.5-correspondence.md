# OIP v0.5 correspondence

This document is part of OIP v0.6.0. It records how this version treats the items of the public OIP v0.5 documents. [Conformance scope](conformance.md) defines the requirement key words.

## Legacy path

The reference legacy codec is a reference compatibility record. It does not interoperate with the wire format of the public v0.5 documents.

## Items of the v0.5 documents

Each row gives the v0.5 item, its treatment in this version and where this version defines it. "Replaced" means this version defines a different mechanism for the same purpose. "Not defined" means this version contains no mechanism for the item.

| v0.5 item | Treatment | This version |
| --- | --- | --- |
| Version string in SemVer form | Replaced. The core carries the integer version 6, and peers negotiate the version per channel. | [Version check](wire-conformance.md#version-check-and-unknown-fields) |
| Timestamps in ISO 8601 | Replaced. Times are unsigned UTC seconds since the Unix epoch in fixed64 fields. | [Canonical signed message](wire-conformance.md#canonical-signed-message) |
| Chain identifiers in CAIP-2 form and display addresses | Replaced. Domains, principals and assets are registered 64-bit handles. | [Canonical signed message](wire-conformance.md#canonical-signed-message) |
| Seven message type discriminators | Kept. Family codes 1 to 7 keep the v0.5 message type numbers and names. | [Canonical field numbers](wire-conformance.md#canonical-field-numbers) |
| Canton origins and the Canton driver attestation fields | Replaced for origins: a Canton domain is a registered domain handle. The driver attestation and party mapping fields are not defined. | [Canonical signed message](wire-conformance.md#canonical-signed-message) |
| GOVERNANCE message type | Changed meaning. Family 7 carries owner handover and authorized epoch installation. Registry, routing table and party mapping changes are not wire operations. | [Operations](operations.md) |
| Wire format and field numbers in a `.proto` schema | Defined. | `proto/oip.proto`, [Canonical field numbers](wire-conformance.md#canonical-field-numbers) |
| Public repository with code generation scripts and version history | Defined. The generation scripts are in `scripts/`. | `scripts/generate-wire.py`, `scripts/render-operations.py` |
| Self-check list as executable tests | Defined as conformance vectors that both language bindings run. | `tests/vectors/`, `scripts/test-wire-interop.py` |
| Message size limits and fragmentation | Size and nesting limits are configuration values of the receiving host. A frame over the limit receives INVALID_FORMAT, and a request whose response could exceed the limit is refused before effect. Fragmentation is not defined, so a message fits in one frame. | [Canonical signed message](wire-conformance.md#canonical-signed-message) |
| Procedure for new error codes and categories | Unknown response codes are accepted as their kind. A procedure for adding codes is not defined. | [Reference outbound Response](wire-conformance.md#reference-outbound-response) |
| Restricted DSL condition expressions | Not defined. The core carries no condition expression. | None |
| Routing registry records and updates ([v0.5 source](https://docs.oraclizer.io/oip-v05/routing/#dynamic-routing-table-updates)) | Changed mechanism. v0.5 populates ChainRegistry, AssetLocationMap, AuthorityRegistry and NodeRegistry through GOVERNANCE routing-table updates. This version takes registrations from host configuration and binds the selected policy fingerprint into retained authority state; those routing-table updates are not wire operations. A standalone signed registry-record encoding is not defined. | [Identity and ownership handover](identity-handover.md), [JSON policy binding](json-encodings.md#reference-signing-inputs) |
| Verifiable primary-finality preservation after lock expiry or reconciliation ([v0.5 invariant](https://docs.oraclizer.io/oip-v05/state-management/#pending-sync-queue-invariants)) | Partial scope. The reference binds primary decisions, pending source obligations, authoritative historical prefixes and secondary work into its durable authority state and authenticates exact recovery/archive inputs. A deployment-wide long-term archive policy, retention periods, compaction and storage tiers are not defined. The operational strategy remains open as recorded in [v0.5 Open Issues](https://docs.oraclizer.io/oip-v05/open-issues/#long-term-storage-strategy-for-primary-finality); an archive mechanism alone does not settle that policy. | [Authenticated persistence and recovery](persistent-recovery.md), [Primary decisions and publication](authoritative-outcomes.md) |
| Multi-Signatory authority field | Not defined. A frame names one principal and carries one SINGLE signature. Owner handover requires separate consents of the current owner and the successor. | [Identity and ownership handover](identity-handover.md) |

## Error codes

v0.6 response codes are numbers grouped by kind. [Effect and retry by code](wire-conformance.md#effect-and-retry-by-code) gives the closest v0.5 code for each v0.6 code. The v0.5 codes with no listed counterpart have no v0.6 response code of their own.
